Approver attribution — measured, not assumed

fueltrade.operation attaches the approver to the commit record's :payload only; :value is left exactly as the advisor proposed it. Whether the approver then survives is decided per-effect by fueltrade.store/commit-record!. This table is derived at render time by walking each register and testing for the key, so it self-corrects if the store is later changed — it is not a hardcoded verdict.

Attribution gap observed in this run. The assessment branch of commit-record! persists payload, so the approver survives there. The two actuation branches (:order/mark-delivered, :order/mark-invoiced) recompute their record from fueltrade.registry and read neither payload nor value — so for the two acts that actually move product and money, the approver is not in the book of record. (The fuel-order branch persists value, which would drop the approver too, but no fuel-order upsert was human-approved in this run, so it is reported as such rather than counted as a loss.)

Who signed off is shown below from the audit facts instead, and is labelled (audit only — not in commit record) wherever that is the case. This page does not omit the approver: a reader must be able to tell “nobody approved” from “the store did not keep it”.
